# 闲亭 · 演进建议（可玩性 / 专业性）

## 一、当前定位
家庭/朋友局的"打开即玩"棋牌 + 掌机游戏库：无账号、无充值、娱乐分只记输赢，靠局域网或手机当主机开局。

## 二、下一步该补的（按收益排序）

### 1. 服务端成为"内容中枢"（已起步）
- 游戏库改由服务端托管：NAS 上 `data/library/` 放 ROM/H5 包，各端 `/api/library` 拉取，版本天然一致（本轮已实现接口与客户端导入）。
- 继续补：库文件版本号与增量更新、按平台分目录、房主推送"本桌统一游戏"。
- 收益：一次上传全体可用，避免每台手机各自导入。

### 2. 对局体验的"商业级"细节
- 结算页：名次奖牌 + 分数滚动 + 一句人话点评 + 换桌/再来一局。
- 出牌节奏：可撤销窗口、出牌飞行、牌面抖动、连击语音（已完成基础版）。
- 听牌/番型/进贡等专属演出，一款一款对齐主流产品。
- 收益：直接决定"像不像正经棋牌产品"，是留存的主因。

### 3. 房间与社交
- 房间列表（同网段自动发现所有房）、观战席、房主踢人/换玩法。
- 固定牌搭子（记住上次同桌的人，一键再开）。
- 收益：家庭场景复访率高于随机匹配。

### 4. 数据与成长
- 本机战绩：局数、胜率、最高倍数、连胜；不做排行、不做付费。
- 娱乐分只做"手气曲线"，避免变成赌博暗示。
- 收益：给"常来玩"一个理由，同时守住合规边界。

### 5. 工程可靠性
- 服务端：systemd 守护 + 日志轮转 + 每日备份 `data/`；房间落盘已有，补"崩溃后自动恢复房间"。
- 客户端：断线重连状态机可视化（已有横幅），补"离线可转单机继续"。
- 安装包：x86/arm 双包 + Docker Compose（本轮交付）。

## 三、明确不做
- 充值、兑换、转赠、抽奖（合规红线）。
- 在线匹配与陌生人社交（家庭场景不需要，且带来审核成本）。
- 依赖公网服务的强绑定功能（NAS 自托管是卖点）。

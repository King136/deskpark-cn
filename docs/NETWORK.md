# 联机能力盘点与局域网方案

> 对应诉求：*梳理单机/联机/连服务端的功能状况，评估能否承接局域网联机（自发现、自接棒、输入地址全网联机）。*
> 本文是现状盘点 + 缺口评估 + 落地方案，改代码时以本文的分层为准。

## 一、三种链路，共用一套协议

单机、局域网、全网**跑的是同一个房间内核**，区别只在「谁在跑 Hub、WebSocket 连到哪」。

| 链路 | Hub 跑在哪 | 客户端连到 | 入口 |
|---|---|---|---|
| 单人（对 AI） | 页面内 `LocalController` | 无网络 | 大厅卡片「单人」→ `#/play/:gameId` |
| 局域网 · 他人主机 | 对方手机的 Android `ParkHost` 服务 | `ws://<对方IP>:8787/ws` | 大厅 `lanbar` 扫到后一点即连 |
| 局域网 · 本机主机 | 本机 `ParkHost` + `HostCore` | `ws://127.0.0.1:8787/ws` | 设置页「把本机变成主机」 |
| 全网 | `@park/server` 进程（飞牛/Docker/VPS） | `ws://<域名或IP>/ws` | 设置页手填地址 |

关键设计：`HostCore` 直接 new 的是 `@park/server` 里的 `Hub`，**不是**另写一套。
服务端 Hub 只要求「给这条连接一个发送函数」，所以原生层把 TCP 字节桥进来就能跑，
协议、座位、娱乐分、掉线托管、结算全部与线上一致，不会出现两套行为。

代码位置：

| 能力 | 文件 |
|---|---|
| 房间内核（服务端同源） | `packages/server/src/rooms/*`，网页侧封装 `apps/web/src/lib/hostCore.ts` |
| 原生主机桥（Android 插件） | `apps/web/src/lib/localHost.ts` ↔ `android/.../ParkHostPlugin.java` |
| 局域网自发现 | `apps/web/src/lib/discover.ts` |
| 地址归一化 / 默认地址 | `apps/web/src/lib/platform.ts`（`normalizeServer` / `serverUrl`） |
| 连接与重连 | `apps/web/src/lib/online.ts` |
| 大厅发现条 | `apps/web/src/screens/Home.tsx`（`.lanbar`） |
| 设置页联机配置 | `apps/web/src/screens/SettingsSheet.tsx`（`ServerSection`） |

## 二、能力矩阵

| 能力 | PC 浏览器 | Android 壳 | 说明 |
|---|---|---|---|
| 单人 / 对 AI | ✅ | ✅ | 完全离线 |
| 手填地址连服务端（全网） | ✅ | ✅ | `normalizeServer` 兼容 `ip:port`、`http(s)://`、`wss://…/ws` |
| 当主机（局域网） | ❌ | ✅ | 浏览器不能监听端口，这是浏览器沙箱的硬限制 |
| 扫同网段找主机 | ⚠️ 有条件 | ✅ | 详见下方「缺口 1」 |
| 按房号反查哪台机器持有该房 | ✅ | ✅ | `findRoomHost(code)` |
| 房主掉线后无缝接管牌局 | ❌ | ❌ | 协议没有状态快照，详见「缺口 2」 |
| 同房号重建（接棒，牌局重开） | ❌ | ✅ | 原生起主机后可手动开同号房 |

## 三、三个缺口

### 缺口 1：浏览器扫不到局域网（已修）

原实现 `scanLan()` 只认原生 `ParkHost.lanIp()`，浏览器里恒返回空数组 ——
也就是说**在 PC 上打开网页，局域网自发现等于没有**。

修复（本轮）：

- 新增 `guessLanPrefix()`：页面若由局域网主机提供（`location.hostname` 是私网 IP），
  就用它所在的 /24 去扫，零配置即可发现同网段的其它主机；
- `scanLan(prefix?)` 支持显式网段，设置页新增「网段输入 + 扫描局域网」区块，
  扫到主机直接点一下就连过去；
- IP 私网判断覆盖 `10/8`、`172.16–31`、`192.168/16`、`169.254/16`（链路本地）。

仍未覆盖：页面部署在公网域名、而玩家与主机在同一局域网 —— 此时浏览器没有任何手段
得到本机私网 IP（WebRTC 的 local candidate 已被浏览器默认屏蔽）。这类场景要求玩家
手填一次网段（如 `192.168.1`），填过一次后可记住。

### 缺口 2：接棒目前只能「同号重建」，做不到无缝

「接棒」的本质是把**权威状态**从 A 机器搬到 B 机器。现状：

- 服务端 Hub 持有完整 `state`；
- 客户端只收到 `game` 消息里的 `view` —— 那是**该座位的视角**，含隐藏信息裁剪
  （麻将看不到对手手牌、海战看不到对方舰位）；
- 协议 `ClientMessage` / `ServerMessage` 里没有 `exportState` / `importState` / `resume`。

所以客户端**无法**凭手里的数据重建一局进行中的牌局。真要无缝接棒，需要：

1. 引擎层给每个 `GameDefinition` 加 `serialize(state)` / `deserialize(json)`（多数游戏 state 已是纯数据，成本不高）；
2. 协议加 `{ t: 'takeover'; snapshot: ... }`，由原主机在退出前广播快照，或由客户端各自保管最新快照；
3. 新房主 `importState` 后 `resume`，其余客户端按新地址重连并 `join`（带 `resumeToken` 免重座）。

这是 P1 工作量（协议 + 引擎 + 客户端三处），不建议塞进当前版本。

**本轮可交付的接棒形态（已具备，需引导）**：

```
房主掉线 → 任一 Android 设备「设置 → 把本机变成主机」
        → 用同一房号新建（房号可自定义/沿用）
        → 其余人用同号重新加入 → 座位与娱乐分延续，牌局从下一局开始
```

要做的是把这个路径在掉线提示里讲清楚，而不是让玩家对着「连接已断开」发呆。

### 缺口 3：没有「主机在线状态」的常驻指示

`lanbar` 每 10 秒扫一次（`setInterval`），但只在无主机时显示「未发现主机」。
主机中途挂掉时，玩家要等到操作超时才发现。建议后续把 `online.ts` 的
`status`（connecting/open/closed）提升为牌桌顶部的一个小圆点，与现有 `.hud__dot` 合并。

## 五、验收方式

局域网三件事，各有一条可复现的验收路径：

1. **自发现**：A 机开「本机当主机」→ B 机大厅 10 秒内出现 `A 的 IP · N 间房` 芯片；
2. **同号接管**：A 机建房 → 杀掉 A 的进程 → B 机开主机并建同号房 → C 机用同号进入，座位表与娱乐分正常；
3. **全网**：任一端填 `wss://game.example.com/ws` → 「探测主机」返回「主机在线 · 闲亭 · N 间房」。

## 六、数据同步（WebDAV）

玩家数据（设置、形象、存档、游戏库）都落在 `localStorage` 的 `park.*` 键上。
把这些键打包成一个 JSON 直接 PUT 到自己的网盘，就实现了「换设备无缝迁移」，
不需要自建账号体系，也不依赖官方服务器。

实现：`apps/web/src/lib/webdav.ts` + 设置页 `SyncSection`。

### 备份包格式

```json
{
  "app": "xanting",
  "version": 1,
  "exportedAt": "2026-11-18T10:31:51.291Z",
  "device": "Linux x86_64",
  "data": { "park.settings": { "felt": "indigo", "...": "..." }, "park.profile": { "...": "..." } }
}
```

- 只收 `park.*` 前缀的键；
- 刻意跳过两个键：`park.dav`（含密码）与 `park.server`（联机地址跟网络绑定，换设备就该重填）；
- `app` / `version` 用于识别「这是不是闲亭的备份」，避免误覆盖别的 JSON。

### 冲突策略

不做自动合并，只做「显式覆盖」：

| 场景 | 行为 |
|---|---|
| 点「备份到云端」 | 本机 → 云端，直接覆盖，记录同步时间到 `park.sync` |
| 点「从云端恢复」 | 先下载并展示云端备份时间/来源设备，用户点「确认覆盖」才写本机 |
| 开启「启动自动比对」 | 启动后 HEAD 一次云端文件，比 `park.sync.at` 新就 toast 提示，**绝不自动覆盖** |

恢复后 `location.reload()`：各 store 是模块级单例，内存值与新写入的 localStorage
需要重新初始化，重载是最省事也最不容易出错的做法。

### CORS 现实

浏览器里对第三方域名发 WebDAV 请求会被跨域拦（坚果云等网盘通常不放行）。
`webdav.ts` 把这类失败翻译成可读文案（「网盘不允许浏览器跨域，换成 App 里试」），
不报「密码错误」误导用户。Android 壳走原生 HTTP，不受此限制。
